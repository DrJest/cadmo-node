I tag

<%= valore %>   stampa con l'escape   ← sempre, per i dati
<%- html %>     stampa così com'è     ← solo per gli include

<% if (locals.errore) { %> … <% } %>   ← variabile forse assente

Post/Redirect/Get

POST /libri       → 303 See Other · Location: /libri/16
GET  /libri/16    → 200 (la pagina)
↻ ricarica        → ripete solo il GET: niente doppioni

res.redirect(303, `/libri/${libro.id}`);
eliminare: <form method="POST" action="/libri/3/elimina">   mai un link!

Missione B: Modificare un libro

Focus: un partial per due form, valori iniziali, PRG anche nella modifica

  1. Sposta i campi del form di nuovo.ejs (non il <form>) in views/partials/campi-libro.ejs e includilo in nuovo.ejs.
  2. Crea GET /libri/:id/modifica: la vista modifica.ejs usa lo stesso partial, con i valori presi dal libro, e invia il form a POST /libri/:id/modifica.
  3. Nella POST: stesso schema, stessi errori (422); se va tutto bene aggiorna il libro (aggiungi aggiorna(id, dati) al service) e fai un 303 verso la scheda.
  4. Aggiungi il link "Modifica" nella scheda del libro. Perché qui va bene un link, e per eliminare no?
// routes/pagine.js
router.get('/libri/:id/modifica', (req, res, next) => {
  const libro = libri.trova(Number(req.params.id));
  if (!libro) return next();
  // i valori iniziali del form sono quelli del libro (disponibile: true → checkbox spuntata)
  res.render('modifica', { titolo: 'Modifica', libro, valori: libro, errori: {}, GENERI });
});

router.post('/libri/:id/modifica', (req, res, next) => {
  const libro = libri.trova(Number(req.params.id));
  if (!libro) return next();
  const r = libroForm.safeParse(req.body);
  if (!r.success) {
    return res.status(422).render('modifica', {
      titolo: 'Modifica', libro, valori: req.body, errori: z.flattenError(r.error).fieldErrors, GENERI,
    });
  }
  libri.aggiorna(libro.id, r.data);
  res.redirect(303, `/libri/${libro.id}`);
});

// services/libri.js — il form manda TUTTI i campi: è una sostituzione, come un PUT
function aggiorna(id, dati) {
  const tutti = leggi();
  const i = tutti.findIndex((l) => l.id === id);
  tutti[i] = { id, ...dati };
  scrivi(tutti);
  return tutti[i];
}
module.exports = { cerca, trova, crea, aggiorna, elimina };
<!-- views/modifica.ejs (nuovo.ejs è uguale, con action="/libri" e un altro titolo) -->
<%- include('partials/testa') %>

<form method="POST" action="/libri/<%= libro.id %>/modifica">
  <%- include('partials/campi-libro') %>
  <button>Salva le modifiche</button>
</form>
<%- include('partials/piede') %>

<!-- views/libro.ejs -->
<a href="/libri/<%= libro.id %>/modifica">Modifica</a>
<!-- Il link apre solo il form (un GET che non cambia niente): va benissimo.
     È il POST del form a modificare. Eliminare con un link, invece, vorrebbe dire
     un GET che cambia i dati: anteprime e crawler potrebbero farlo da soli. -->
