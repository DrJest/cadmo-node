HTTP e server web

Esercitazioni Modulo 3

Il protocollo HTTP, il client HTTP e il primo server con il modulo http: routing, JSON, query string e body delle POST. Tutto gira qui nel browser, ma il codice è Node.js vero.

1. Guida rapida: il modulo http

Server minimo

Una callback per ogni richiesta; listen tiene acceso il processo.

const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('Ciao!');
});

server.listen(3000, () => console.log('http://localhost:3000'));

Rispondere in JSON

Header giusto + JSON.stringify. Una sola res.end() per richiesta!

function inviaJson(res, status, dati, headers = {}) {
  res.writeHead(status, {
    'Content-Type': 'application/json; charset=utf-8',
    ...headers,
  });
  res.end(JSON.stringify(dati));
}

inviaJson(res, 201, nuovo, { Location: '/api/libri/4' });

Routing e query string

req.url include la query: usa new URL() per separarle.

const url = new URL(req.url, 'http://localhost');
const parti = url.pathname.split('/').filter(Boolean);

if (req.method === 'GET' && url.pathname === '/saluta') {
  const nome = url.searchParams.get('nome'); // null se manca
  return inviaJson(res, 200, { messaggio: `Ciao ${nome}!` });
}
inviaJson(res, 404, { errore: 'Non trovato' }); // ultimo ramo

Body di una POST

Il body arriva a pezzi: leggilo tutto, poi JSON.parse dentro try/catch.

const server = http.createServer(async (req, res) => {
  let body = '';
  for await (const chunk of req) body += chunk;

  let dati;
  try {
    dati = JSON.parse(body);
  } catch {
    return inviaJson(res, 400, { errore: 'JSON non valido' });
  }
  // ... usa dati
});

Status code da avere sotto mano

Scegli il codice che descrive davvero l'esito: il client (e chi lo programma) ti ringrazierà.

4. Missioni sul tuo PC

Ora tutto per davvero: terminale, VS Code, browser e curl. Su Windows PowerShell scrivi curl.exe invece di curl.

Missione 1: Il cantiere

Focus: progetto, script npm, node --watch

1. Crea la cartella pizzeria, entraci e inizializza il progetto con npm init -y.

2. Crea server.js con il server minimo della guida rapida.

3. Aggiungi gli script "dev": "node --watch server.js" e "start": "node server.js" (con npm pkg set o modificando il file).

4. Avvia con npm run dev, cambia il testo della risposta, salva e osserva il riavvio automatico.

$ mkdir pizzeria
$ cd pizzeria
$ npm init -y
$ code server.js # incolla il server minimo e salva
$ npm pkg set scripts.dev="node --watch server.js" scripts.start="node server.js"
$ npm run dev
# apri http://localhost:3000, modifica server.js, salva: Node riavvia da solo

Missione 3: Rompi il server (apposta)

Focus: leggere i crash

1. Nella route GET / aggiungi una res.setHeader('X-Test', '1') dopo la res.end(). Fai la richiesta: cosa succede al server? Leggi con calma lo stack trace (file, riga, colonna).

2. Ripristina, poi aggiungi una route GET /boom che esegue JSON.parse('{rotto') senza try/catch. Visitala: il server si spegne. Le altre richieste ora funzionano?

3. Con npm run dev (watch) il server ripartirà solo quando salvi il file: in produzione invece servirebbe un "process manager". Correggi entrambi gli errori.

4. Domanda: perché in una route è meglio rispondere 500 con un try/catch invece di lasciare che il processo crashi?

// 1. Errore: Error [ERR_HTTP_HEADERS_SENT]: Cannot set headers after they are sent to the client
// Il processo termina: TUTTI gli utenti restano senza servizio.
// 2. SyntaxError non gestito → crash. Le richieste successive: "Connection refused".
// Correzione per /boom:
try {
  const dati = JSON.parse('{rotto');
  inviaJson(res, 200, dati);
} catch (err) {
  console.error(err);
  inviaJson(res, 500, { errore: 'Errore interno del server' });
}
// 4. Un server è condiviso da tutti: un errore su UNA richiesta non deve spegnerlo per tutti gli altri.
