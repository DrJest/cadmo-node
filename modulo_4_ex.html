1. Guida rapida

Lo scheletro

const express = require('express');
const app = express();
app.use(express.json());          // per leggere req.body

app.get('/', (req, res) => res.send('Ciao!'));

app.listen(3000, () =>
  console.log('Server su http://localhost:3000'));

Dati nella richiesta

// GET /api/libri/42?formato=breve
app.get('/api/libri/:id', (req, res) => {
  req.params.id;       // '42'   (stringa!)
  req.query.formato;   // 'breve' (o undefined)
  req.get('Accept');   // un header
});
// POST con Content-Type: application/json
req.body;              // { titolo: '...', ... }

Rispondere

res.json(dati);                          // 200
res.status(201).location(url).json(nuovo);
res.status(400).json({ errore: '...' });
res.status(404).json({ errore: '...' });
res.sendStatus(204);                     // nessun body
// una sola risposta: dopo un errore → return!

Insidie di Express 5

app.get('*', …)            // ❌ PathError all'avvio
app.use((req, res) => …)   // ✅ "tutto il resto", in fondo
app.get('/a/:id?', …)      // ❌ PathError
app.get('/a{/:id}', …)     // ✅ parte opzionale
// rotte fisse PRIMA di quelle con :parametri
// senza express.json() → req.body === undefined

Missione A: Il primo server Express vero

Focus: installazione, node --watch, curl

  1. Crea il progetto corso-node/lezione4, installa Express e controlla nel package.json che sia la versione 5.
  2. Copia la soluzione del Lab 1 in server.js e aggiungi lo script dev con node --watch.
  3. Apri http://localhost:3000/api/info nel browser, poi con curl -i: quali header aggiunge Express?
  4. Con il server acceso, cambia il testo di GET / e salva: cosa succede nel terminale?
mkdir -p corso-node/lezione4 && cd corso-node/lezione4
npm init -y
npm install express
npm pkg get dependencies          # { "express": "^5.x.x" }
code server.js                    # incolla la soluzione del Lab 1

npm run dev

# al salvataggio: "Restarting 'server.js'" e il server riparte da solo

Missione C: Rompi Express (di proposito)

Focus: leggere gli errori

  1. Aggiungi app.get('*', …): il server parte? Leggi il messaggio e cerca la soluzione nel link che ti suggerisce.
  2. Scrivi una rotta che fa throw new Error('ops'): cosa vede il browser? Cosa compare nel terminale? Il server è ancora acceso?
  3. Ora la stessa cosa in una rotta async dopo un await: cambia qualcosa?
  4. Togli app.use(express.json()) e fai una POST: che errore ottieni e perché?
  5. Lancia il server con NODE_ENV=production e ripeti il punto 2: cosa cambia nella pagina d'errore?
1. PathError [TypeError]: Missing parameter name at index 1: *
   → il server non parte. Usa app.use((req, res) => ...) in fondo, oppure '/*splat'.
2. Il browser riceve 500 con lo stack dell'errore; nel terminale c'è lo stack;
   il server resta acceso e risponde alle altre richieste.
3. Con Express 5 nessuna differenza: anche gli errori async diventano un 500.
   (Con Express 4 la promise rifiutata avrebbe fatto crashare il processo.)
4. TypeError: Cannot destructure property '...' of 'req.body' as it is undefined.
   Senza express.json() nessuno legge il body.
5. In produzione la pagina mostra solo "Internal Server Error": lo stack non
   va mai mostrato agli utenti (rivela dettagli interni del server).
